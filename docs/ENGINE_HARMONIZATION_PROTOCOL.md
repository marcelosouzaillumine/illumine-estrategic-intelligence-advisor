# ENGINE HARMONIZATION PROTOCOL

## 1. Objetivo

Este documento define o protocolo obrigatório de harmonização entre todas as engines financeiras, módulos analíticos, scores, advisory systems e interpretadores da plataforma Illumine.

Nenhuma engine pode:
- gerar interpretações isoladas;
- utilizar scoring local conflitante;
- aplicar severidade própria;
- interpretar liquidez sem contexto;
- classificar risco sem causalidade.

Todas as análises devem obedecer:
- MASTER_ARCHITECTURE.md
- MASTER_FINANCIAL_INTELLIGENCE_ENGINE.md
- ENGINE_CAUSALITY_AND_LIQUIDITY_FRAMEWORK.md

---

# 2. Hierarquia Oficial de Interpretação

Toda análise deve seguir:

1. Contexto do segmento
2. Estrutura patrimonial
3. Liquidez contextual
4. Qualidade do capital de giro
5. Sustentabilidade operacional
6. Endividamento
7. Stress financeiro
8. Continuidade empresarial

A plataforma NÃO pode inverter essa ordem.

---

# 3. Proibição de Engines Independentes

Nenhum componente pode:
- criar score próprio;
- interpretar risco isoladamente;
- definir severidade própria;
- criar advisory autônomo;
- penalizar ativos sem política oficial.

Toda engine deve utilizar:
- taxonomia oficial;
- pesos oficiais;
- causalidade oficial;
- regras oficiais de conversibilidade.

---

# 4. Taxonomia Única de Severidade

Toda a plataforma deve utilizar exclusivamente:

| Nível | Significado |
|---|---|
| Saudável | Estrutura robusta |
| Estável | Operação funcional |
| Sensível | Atenção requerida |
| Fragilizado | Pressão estrutural |
| Crítico | Alto risco |
| Ruptura | Continuidade ameaçada |

É proibido:
- dramatização automática;
- colapso implícito;
- linguagem catastrófica sem evidência estrutural.

---

# 5. Liquidez Contextual Obrigatória

Toda leitura de liquidez deve considerar:
- conversibilidade;
- segmento;
- ciclo operacional;
- dependência de estoque;
- aging de recebíveis;
- concentração de clientes;
- dependência operacional.

Liquidez seca isoladamente NÃO pode definir insolvência.

---

# 6. Materialidade Obrigatória

Indicadores isolados NÃO podem destruir scores globais sem:
- relevância;
- persistência;
- impacto sistêmico;
- correlação estrutural.

---

# 7. Harmonização dos Scores

Todos os scores da plataforma devem:
- compartilhar pesos oficiais;
- compartilhar taxonomia;
- compartilhar severidade;
- compartilhar causalidade.

É proibido:
- score contraditório;
- engine conflitante;
- risco incompatível.

---

# 8. Advisory Intelligence

Os advisories devem separar:

| Tipo | Objetivo |
|---|---|
| Problema Primário | Causa estrutural |
| Problema Secundário | Efeito indireto |
| Risco Principal | Principal ameaça |
| Impacto Operacional | Consequência |
| Recomendação Estratégica | Correção causal |

---

# 9. Interpretação Proibida

A plataforma NÃO pode assumir automaticamente:

- prejuízo = falência;
- estoque alto = ruptura;
- liquidez baixa = insolvência;
- EBITDA negativo = inviabilidade imediata;
- dívida = colapso financeiro.

Toda interpretação deve ser contextualizada.

---

# 10. Objetivo Final

A plataforma Illumine deve operar como:
- sistema de inteligência financeira;
- motor de causalidade empresarial;
- advisory executivo;
- plataforma de suporte estratégico;
- engine contextual de governança corporativa.
